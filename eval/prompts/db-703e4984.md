Bug report - clear advance OS review documents are lost (backend + data model, `app/`).

In the clear-advance approval flow, the OS reviewer uploads supporting documents in the
detail view. The client sends them with the OS Review approve action:

  POST /ClearAdvanceService/approve
  { "id": "<clearId>", "osDocuments": [ { "name": "...", "documentId": "...", "href": "...", "mimeType": "..." } ] }

After the approval, `GET /ClearAdvance/<clearId>` does not return the documents. They are
lost on reload, and the owner and later reviewers cannot see them.

Expected: when the reviewer at the OS step approves, the `osDocuments` array is stored on
the ClearAdvance record and returned by `GET /ClearAdvance/<id>` as field `osDocuments`.

The data model is generated. The domain spec is in `app/spec/domain/*.domain.yaml`.
Regenerate `app/generated/` (including the DB table definitions) with `cd app && pnpm gen`.
Run backend tests with `cd app && npx tsx --test test/<file>.test.ts`.
Do not commit. Do not push.
