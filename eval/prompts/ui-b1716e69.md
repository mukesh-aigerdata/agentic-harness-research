Bug report (log #274) - trip expense sheet, frontend (`web/`).

On the trip reimbursement expense sheet (`ReimbExpenseTab`, also used embedded in the
trip clear-advance editor):

1. When the sheet has only one Transportation box, that box shows no remove button.
2. When the sheet has only one Accommodation box, its remove button is disabled.

Users must be able to remove every Transportation and Accommodation box, the last one too.
Both remove buttons must be real, enabled `<button type="button">` elements with an
accessible name (`aria-label`) from the translation function:
- Transportation box: `t('common.remove', 'Remove')`, so the name is "Remove".
- Accommodation box: `t('tooltip.removeLine')`, the same key as its tooltip.

Also: a sheet that was already saved must reopen exactly as saved. If the user removed all
Transportation or Accommodation boxes and saved, reopening must not add a blank box back.
A sheet counts as saved when the record has at least one item in any of its expense
arrays: `transportations`, `perdiems`, `accommodations`, `tripExpenses` or
`entertainmentExpenses`. A sheet that was never saved (all of those empty or missing)
still opens with one blank Transportation box and one blank Accommodation box.

Fix the bug in the source code. Run the web unit tests with `cd web && npx vitest run <file>`.
Do not commit. Do not push.
